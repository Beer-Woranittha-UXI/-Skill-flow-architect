# Review protocol — ตบ / เพิ่ม / แก้ / แนะต่อ โดยไม่แย่งคิด

สกิลนี้มีอยู่เพื่อ **ทำให้ flow ของดีไซเนอร์คมขึ้น** ไม่ใช่เพื่อผลิต flow แทน
ถ้ารันสกิลแล้วได้ flow ทั้งเส้นโดยดีไซเนอร์ไม่ได้คิดอะไรเลย = ทำผิดโจทย์ ไม่ใช่ทำเสร็จเร็ว

## เส้นแบ่งที่ต้องไม่ข้าม

| ทำได้เอง (mechanical — ไม่ต้องขออนุมัติ) | ต้องเสนอแล้วรอดีไซเนอร์เลือก |
|---|---|
| จัด layout / ระยะ / มุมเชื่อม / รูปทรงให้ตรงสเปก | เพิ่มกล่องหรือเส้นใหม่ |
| ใส่ป้าย Yes/No ที่ขาดไป **เมื่อทิศทางชัดจากสิ่งที่เขียนมาแล้ว** | แตก Decision ที่ถามหลายเรื่องออกเป็นหลายอัน |
| แก้รูปทรงที่ใช้ผิดประเภท (เงื่อนไขอยู่ในสี่เหลี่ยม) | เติม edge case หรือ permutation ที่ยังไม่มีใครพูดถึง |
| รวมกล่องที่ข้อความซ้ำกันเป๊ะให้เป็น id เดียว | เปลี่ยนข้อความในกล่อง (copy เป็นงานของคน + writing skill) |
| เรียง id / จัดคอมเมนต์ / เติม header ที่ว่าง | เปลี่ยนลำดับขั้นของ flow หรือเส้นทาง happy path |

เวลาไม่แน่ใจว่าข้อไหนอยู่ฝั่งไหน ให้ถือว่าอยู่ฝั่งขวา — เสนอ ไม่ใช่ทำ

## รูปแบบรายงาน (ใช้ทุกครั้ง)

```markdown
## 1. อ่าน flow ที่ได้มา
<สรุปเส้นทางที่ดีไซเนอร์เขียน 2–4 บรรทัด + happy path + จำนวนกล่อง/Decision>
<ถ้าอ่านเจตนาไม่ออกตรงไหน ถามตรงนั้น อย่าเดาแล้ววาดต่อ>

## 2. ตบให้ตรงสเปก (ทำแล้ว)
| # | ทำอะไร | code |
|---|---|---|
| 1 | ... | G1 |

## 3. ผิดกฎที่ต้องแก้ (R0/R1) — พร้อมทางเลือก
| # | code | ที่ไหน | ปัญหา | ทางเลือก |
|---|---|---|---|---|
| 1 | S7 | d2 | ถาม 2 เรื่องในอันเดียว | (ก) แยกเป็น d2a→d2b (ข) ตัด "และมีสิทธิ์" ออกถ้าไม่ใช่เงื่อนไขจริง |

## 4. ข้อเสนอ (ต้องอนุมัติก่อนวาด)
- **A1** เพิ่ม `<ยอดเงินพอ ใช่หรือไม่?>` ก่อนหน้าชำระเงิน — เพราะ ... [เดา/มีหลักฐาน: ...]
- **A2** ...
> ตอบกลับว่า "รับ A1, A3" หรือ "ไม่รับทั้งหมด" ได้เลย — ข้อที่ยังไม่อนุมัติจะไม่ขึ้น diagram

**ก่อนปิด §4 ต้องกวาด 3 หมวดนี้ทุกหน้า** (`self_check.py` บอกได้แค่ว่าหน้าไหนยังว่าง
ด้วย `E1`/`E2` — ว่าขาดเคสอะไรต้องคนตอบ ดู `flow-rules.md` §4.6)

- **edge case** — ทำสำเร็จแต่เงื่อนไขไม่ปกติ: ของหมด · เกินโควตา · หมดเวลา · ถูกตัดหน้า
- **error state** — ทำไม่สำเร็จ: เน็ตหลุด · ระบบล่ม · ตัดเงินไม่ผ่าน · กดซ้ำ
- **empty state** — ไม่มีข้อมูลให้ดู: ยังไม่เคยใช้ · ลบหมดแล้ว · ค้นไม่เจอ

เสนอเป็นข้อ `A<n>` ตามปกติ ติดป้ายเดา/มีหลักฐาน แล้วรอให้อนุมัติก่อนวาด

## 5. คำถามที่ตอบได้เฉพาะคนทำโปรดักต์
1. ...

## 6. ที่มาของ flow นี้
ดีไซเนอร์เขียนเอง N กล่อง / N เส้น · AI เสนอและได้รับอนุมัติ M กล่อง / M เส้น (M/(N+M) = X%)
```

## Authorship ledger — กันสกิลกลืนงานคน

ทุกครั้งที่ render ให้รายงานสัดส่วน "กล่องที่ดีไซเนอร์เขียน" กับ "กล่องที่มาจากข้อเสนอของ AI"

- ข้อเสนอที่อนุมัติแล้ว ให้เขียนลง `.flow` **พร้อมคอมเมนต์** `# [AI-A1] เหตุผล` ต่อท้ายบรรทัด
  ไล่ย้อนได้ว่าบรรทัดไหนมาจากไหน และถอนออกได้ทีหลัง
- ถ้าสัดส่วนของ AI เกิน **40%** ของกล่องทั้งหมด: หยุด แจ้งดีไซเนอร์ว่าใบนี้กำลังกลายเป็น
  flow ของ AI แล้ว และเสนอให้ถอยกลับไปคุยโครงก่อนแทนที่จะเดินหน้าวาด
- ตัวเลขนี้ไม่ใช่ metric ที่ต้องทำให้สวย มันคือสัญญาณเตือนว่ากำลังแย่งคิดอยู่หรือเปล่า

## เมื่อดีไซเนอร์ยังไม่มีอะไรเลย

ทำสามอย่างนี้แทนการร่างให้ (รวมถึงการร่างตัวอย่างเต็มเส้นให้ลอก)

1. ส่ง `assets/_template.flow` ให้กรอก
2. ถามคำถามตั้งต้น — **ถามเพื่อให้คนคิด ไม่ใช่ถามเพื่อเอาไปคิดแทน**
   - งานนี้ผู้ใช้กำลังพยายามทำอะไรให้เสร็จ (หนึ่งงาน)
   - เริ่มจากการกดอะไร จบเมื่อเห็นอะไร
   - ระหว่างทางมีจุดที่ระบบต้องตัดสินใจกี่จุด แต่ละจุดถามว่าอะไร
   - ถ้าเงื่อนไขไม่ผ่าน ผู้ใช้ควรไปไหน
   - หน้าไหนที่รู้อยู่แล้วว่ามีเคสพิเศษ
3. ถ้าดีไซเนอร์ยืนยันว่าให้ AI ร่างให้ ให้บอกขอบเขตของสกิลนี้ตรง ๆ
   แล้วเสนอทางที่ได้ผลกว่า: เอาหน้าจอ/สเปก/blueprint ที่มีอยู่มาถอดเป็น flow (มีหลักฐาน)
   หรือใช้ `ux-strategist` ทำ blueprint ก่อน แล้ววนกลับมาใบนี้
