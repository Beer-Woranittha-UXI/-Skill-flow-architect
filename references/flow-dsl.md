# .flow DSL — syntax + CLI

ไฟล์ `.flow` คือ **ของดีไซเนอร์** เป็น single source of truth ของ flow หนึ่งเส้น
HTML/SVG เป็นแค่ผลลัพธ์ที่ render จากไฟล์นี้ — แก้ flow ให้แก้ที่ `.flow` เสมอ ไม่แก้ SVG มือ

## Header

| directive | จำเป็น | ความหมาย |
|---|---|---|
| `FLOW <ชื่อ>` | ✅ | ชื่อ flow — หนึ่ง flow ต่อหนึ่งงาน |
| `GOAL <ข้อความ>` | ✅ | เป้าหมายจริงของผู้ใช้ (ไม่ใช่เป้าหมายของระบบ) |
| `OWNER <ชื่อ>` | ✅ | ดีไซเนอร์ผู้คิด flow — ขึ้นหัวกระดาษ ใช้ไล่ที่มาได้ |
| `DATE <YYYY-MM-DD>` | ⬜ | |
| `NOTE <ข้อความ>` | ⬜ | ข้อจำกัด / สิ่งที่ยังไม่แน่ใจ |
| `SPACING edge=500 label=100` | ⬜ | ระยะเส้นขั้นต่ำ / ระยะป้ายจากจุดออก (ค่า default = ตามกฎทีม) |

## Nodes — `<KIND> <id> <ข้อความ>`

> ศัพท์: ในไฟล์นี้ `node` = กล่อง และ `edge` = เส้น (คำที่ DSL ใช้) ส่วนเอกสารอื่นเรียก "กล่อง" กับ "เส้น"

| KIND | รูปทรง | ใช้กับ |
|---|---|---|
| `START` / `END` | วงรี (Terminator) | จุดเริ่มต้น / จุดสิ้นสุด |
| `PAGE` (alias `PROCESS`, `STEP`, `ACTION`) | สี่เหลี่ยมผืนผ้า | หน้า/การกระทำ/ขั้นตอน |
| `DEC` | สี่เหลี่ยมข้าวหลามตัด | เงื่อนไข ตอบ Yes/No |
| `LINK` | chip สี่เหลี่ยมมุมมน | Link To Flow — ต่อไป flow อื่น |

`id` ต้องไม่ซ้ำกัน และ **ข้อความเดียวกันต้องเป็นกล่องเดียวกัน** (หน้าเดิมให้โยงกลับ id เดิม
ไม่สร้างกล่องใหม่) — validator จับข้อนี้ด้วย code `S8b`

## Edges — `<src> <op> <dst>`

| op | เส้นที่ได้ | ความหมายใน template ของ Amm |
|---|---|---|
| `->` | ทึบ + จุดต้นทาง + หัวลูกศร | เส้นโยงปกติ ที่มีการกดแล้วไปหน้าบันทึก และไปต่อ |
| `..>` | ประ + จุดต้นทาง | เส้นโยงปกติ ที่มีการย้อนกลับไปหน้าก่อนหน้า — **ปลายทางต้องเป็นหน้าจอ** (PAGE/START) เท่านั้น (กฎ `S14`) |
| `-Yes->` | ทึบ + ป้าย `Yes` เขียว | เส้นโยงวิ่งออกจาก Diamond: Yes |
| `-No->` | ทึบ + ป้าย `No` แดง | เส้นโยงวิ่งออกจาก Diamond: No |
| `-<ป้าย>->` | ทึบ + ป้ายเทา | ป้ายอื่นที่ไม่ใช่ Yes/No — renderer วาดให้ แต่ validator ฟ้อง `S11` เป็น R0 |
| `~>` | ประเหลือง | เส้น Permutation (สร้างอัตโนมัติจาก `PERM` — ไม่ต้องเขียนเอง) |

ป้ายไทยใช้ได้: `-ใช่->` `-ไม่->` จะถูก normalize เป็น Yes/No
ข้าวหลามตัดหนึ่งอันมีเส้นออก 2 เส้นเท่านั้น (Yes + No) — เงื่อนไขที่เหลือแยกเป็นอันถัดไป

## Permutation

```
PERM p4 ตัดเงินไม่ผ่าน / สลากถูกซื้อตัด / หมดเวลาจอง
```

ได้เส้นประเหลืองวิ่งออกจากกล่อง `p4` ไปยัง note สีเหลืองที่ลิสต์เคสไว้
ใช้บอกว่า "หน้านั้น ๆ มี Permutation (Edge Case)" ตาม legend — ไม่ต้องวาด flow ย่อยในใบนี้

## คอมเมนต์

`#` ขึ้นต้นบรรทัด หรือท้ายบรรทัด = คอมเมนต์ ใช้จดเหตุผล/คำถามค้างไว้ได้
คอมเมนต์ไม่ขึ้น diagram แต่ติดไปกับไฟล์ — ใช้เก็บ "ทำไมเลือกทางนี้" ได้ดี

## CLI

```bash
# render -> HTML + SVG + .meta.json (ไฟล์เดียวจบ เปิดในเบราว์เซอร์ได้เลย)
python3 scripts/render_flow.py path/to/flow.flow -o out.html

# ตรวจกฎ -> R0/R1/R2 (exit 1 ถ้ามี R0)
python3 scripts/self_check.py path/to/flow.flow --meta out.meta.json
python3 scripts/self_check.py path/to/flow.flow --json     # เอาไปทำตารางรายงาน
```

`render_flow.py` คุม geometry ให้ทั้งหมด (จัดซ้าย→ขวา / radius 16 / padding 16–24 /
diamond เท่ากันและรวมทางเข้าที่ปลายซ้าย / เส้น 500px / ป้าย 100px /
เลือกมุมเชื่อมตามประเภทเส้น) — วาดผ่านสคริปต์นี้เท่านั้น
SVG ที่เขียนมือจะหลุดสเปกโดยไม่มีใครรู้ และตรวจย้อนไม่ได้

`.meta.json` เก็บพิกัดจริงของทุกกล่องทุกเส้น ใช้เป็นหลักฐานตอน audit และใช้ส่งต่อ
ให้งาน Wireflow / Figma ในใบถัดไป
